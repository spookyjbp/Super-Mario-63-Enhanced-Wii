# v0.4.1 source correction record

Reference: Runouw/Super-Mario-63 at `83e81fb6b80d11c4119e420d25298000a6e13f66`.
All paths below are under `Super_Mario_63_2010`.

## Physics/control corrections (commit 1)

- `DOMDocument.xml:5540–5610,6000–6050,6150–6168,6265–6290`:
  water detection uses the feet minus one quarter of the collider height;
  deep-water gravity is 1/3; resistance layers are 0.05/1.01, 0/1.001, then
  0.05/1.1 vertically and 0.05/1.05 horizontally. Up begins a -6 impulse
  (-4 while Down is also held), then sustains -0.2 per source frame; Down adds
  +0.3. A new impulse requires release after more than five source frames.
  Water entry damps high downward speed by 0.7 then all vertical speed by 0.9.
  The source's left-entry `xpseed` typo is retained (no mirrored +2 impulse).
- `Char/Mario CLIPS/Mario Main.xml` frame `Spin` initializes speed 15.
  `Mario (none) Spin Attack.xml` supplies the exact speed decay, sqrt lift,
  vertical drag, Down acceleration and ground/air stop thresholds 5/3.
  `DOMDocument.xml:5966` permits spin initiation only above vertical speed -3;
  an active spin cannot be refreshed by pressing X. Held X can start a new
  attack after the previous one ends. Rapid alternating directions boost speed
  with `speed*0.8+15`, rather than an arbitrary unlimited upward impulse.
- `Mario (None) Dive.xml:145–177`: backflip starts from a slow grounded dive
  with Up opposite the stored facing. Preserve the actual backward impulse
  `(0.75*vx) - ((0.75*vx)-target)/5`, target opposite facing at 30 source units.
  `Mario Backflip.xml` lasts 22 source frames; its control does not flip facing.
  Slow Down+Up does not invent the v0.4 forced forward roll; forward recovery
  requires speed >3, clip frame >2, and a non-sloped floor.

These recurrences now run on a 32 Hz source clock nested in fixed 60 Hz updates.
Collision and position integration remain 60 Hz, and ordinary land-jump tuning
is retained. This is a documented adaptation, not proof of identical trajectories
or script execution ordering. Tests compare recurrence values and timing,
including repeat spins, finite fall, water strokes and both backflip directions.
No Dolphin/original-game side-by-side verification has been performed here.

## Animation correction and asset boundary (commit 2)

`Mario Main.xml` zero-based frames 2/3 reference `Mario (None) Air - 2` and
`Air - 1`, respectively. `DOMDocument.xml` selects frame 3 until vertical speed
exceeds 2 and frame 4 afterward. The previous Wii mapping was reversed.
The fallback now uses the correct two existing frames, retains their native-left
compensation, and shows the existing landing pose on normal landing without
changing ordinary jump velocities or adding a forced landing lock.

The private source-pose converter restores the original Slide bitmap and its
matrix for grounded Down, and the original four swim poses. Source single and
double jumps share the ordinary ascent clip; no distinct double animation was
found in this path. The third jump references `Mario (none) Frontflip.xml`, which
contains a 22-frame counter-clockwise motion tween followed by recovery. Backflip
contains a clockwise motion tween over frames 3..21. The old generic 720-degree
rotation has been removed rather than presented as faithful. Exact rendered
triple/backflip clips can now be exported from the original compiled SWF through
the optional private pipeline described below. Safe upright fallbacks remain
when no private artwork is installed.

## Original rendered tween export (commit 3)

`Publish/Super_Mario_63_2010.swf` at the same source revision has SHA-256
`6f8dc22d74963cb75928fcac6ad67769384c3088bb419f9995e24b81d8411e1c`.
`tools/export_source_clips.py` validates that hash, then uses JPEXS FFDec to
render DefineSprite 1088 (22-frame bare backflip) and 1093 (30-frame bare
frontflip/triple jump). The original compiled transforms supply every frame;
the Wii code does not interpolate an invented rotation. SVG registration is
preserved in twips and playback uses the source 32 Hz duration.

Static SWF export does not execute ActionScript. DefineSprite 1003's Wing Code
normally hides its wings when `WingCap` is false; the exporter explicitly selects
that blank state in a private temporary SWF. This does not change gameplay or
the source checkout. It is tested against a synthetic SWF. Conditional FLUDD
composites are not exported as though their scripts had executed correctly.
The generated local pack parsed successfully with 60 frames, including both
complete bare-Mario tweens. This validates export structure, not Dolphin output.

FLUDD references examined: `Char/Fludd CLIPS/Fludd Side.xml`, `Fludd Side Front.xml`,
`Dynamic Fludd Nozzle Clip.xml`, `Fludd Front Code.xml`, `Fludd Backwards.xml`,
`Char/Mario CLIPS/Mario Wait WaterBlast.xml`, `Rocket WaterBlast.xml`, and the
nozzle-specific air/swim/flip clips. These combine bitmap fills, nested symbols,
conditional scripts and water animations. The repository does not grant an
explicit new asset redistribution license. No new original PNGs are committed.
A validated user-provided art pipeline is supplied, but authentic composite FLUDD
and water rendering is **not completed** by this patch. See private-player-art.md.

## Six-issue status

1. Down control side effect corrected. Correct original grounded pose is available
   through the private source-pose pack; safe standing fallback without it.
2. Ordinary ascent/descent mapping and normal landing transition corrected; source
   single/double shared pose retained. The original 30-frame bare triple tween is
   available through the optional private SWF export pipeline.
3. Backward impulse checked in both directions, generic walk override removed
   during the original 22-frame backflip and facing retained. Complete original
   22-frame visual motion tween is available through the same private pipeline.
4. Stroke/resistance/entry/surface logic corrected using source-frame recurrences.
   Four source swimming poses are available through the private pack. Collision
   integration and the rest of the port remain adaptations, not proven identical.
5. **Incomplete.** Loader/export interfaces and command-level checks are ready;
   authentic equipment, nozzle attachments and water composite clips still need
   rendered exports and further state/timing verification. No fake water squares.
6. Repeat spins enabled with source timing, initiation restrictions, decay, drag,
   lift, Down behavior and directional boosts. Spamming buttons cannot reset an
   active spin. Tests cover repeated attacks, held inputs and alternating
   directions without unbounded ascent. Existing spin UV direction is retained.

Collision, terrain queries, world data, camera and fixed 60 Hz integration are
unchanged. Three controllers retain the same buttons, with spin-held state now
read so holding the spin button can repeat when source rules permit. Swimming
Up (A or stick/D-pad up) begins a stroke; holding sustains it; release after the
five-source-frame minimum to stroke again. Down descends. No nozzle movement
rebalancing or unrelated Story Mode features were added.

This is a staged correction release, not all six issues completed and not a
claim of gameplay accuracy. All changes require Dolphin comparison against the
original before any visual or trajectory accuracy claim. Correct conditional
FLUDD exports (including nozzle-specific body variants), water emission state
mapping and original-game comparison remain prerequisites for issue 5.
